# container-ci — agent context

Go commands (zero third-party dependencies) that connect CI systems to Apple `container` on a
Mac: one fresh container per job, driven only through the `container` CLI.

## Product

- **Users:** Mac CI hosts on Apple silicon whose GitLab Runner uses this custom executor.
- **Related:** Apple `container`; macOS jobs need a runtime plugin that meets the contract in
  [ADR 0004](docs/adr/adr_0004_one_repository_for_ci_integrations.md).
- **Comparable:** CI executors that start one VM or container per job.
- **Research keywords:** GitLab Runner custom executor, Apple container, container runtime
  plugin, Virtualization.framework, ephemeral CI runner.

## Setup

Run `grim install` once after cloning and again after every change to `grimoire.lock`. It installs
the skills, rules, bundles and MCP server that `grimoire.toml` declares into `.claude/`,
`.agents/skills/` and `.mcp.json`. Git ignores the installed skills, rules and `.mcp.json`;
`grimoire.toml` and `grimoire.lock` are tracked.

`grimoire.lock` pins every artifact to a digest, so a new release never arrives on its own. Run
`grim status --check` now and then: it reports `update_available` for every artifact whose
declared tag has moved. `grim update` then pulls the new versions and rewrites `grimoire.lock`.
Review the lock diff and commit it on its own.

`.claude/agents/hex-*.md` and `.agents/memory/hex.md` are tracked project configuration: the
model and effort per hex worker class, and the hex pointers. `/hex-init` changes them; a fresh
clone needs only `grim install`.

## Verification

Run `task test` before considering any change complete — gofmt check, `go vet`, and
`go test -race`. Run `task check` before proposing a merge. When `task` is not on `PATH`, run
`ocx exec -g build -- task test`: the `build` group carries Go **and** task.
In a hex run (a /hex-execute pipeline or step), the run's integration and release gates
satisfy "verify before commit"; commits use `--no-verify`.

- Selective tests: `ocx exec -g build -- go test -race ./internal/<pkg>/...` for the package a
  change touches; `task test` still runs the full suite.
- Fresh gate: `GOFLAGS=-count=1 task check` runs the full gate without the test cache.
- Generated files: `ocx.lock` (regenerated by `task lock`) and `grimoire.lock` (by `grim lock`)
  are never edited by hand, and pipelines never commit them.
  `internal/container/testdata/list.json` is captured `container list --all --format json` output.

`task test:e2e` runs a whole job against the host's running container services. It creates
and deletes real containers named `gitlab-e2e…`.

## Git — commits, merge requests, pushing

- **Never attribute a commit or MR to an AI.** No `Co-Authored-By` trailer, no tool footer.
- **Commit messages and MR descriptions are bullet points, reduced to essentials.** What
  changed, never why.
- **Never push**, open an MR, tag or release. Propose the exact command.

## Binding rules

- **Zero third-party dependencies** — this repository and the Go standard library only.
- **Scope is CI integrations on the `container` CLI** — runtimes, images and host provisioning
  stay out ([ADR 0004](docs/adr/adr_0004_one_repository_for_ci_integrations.md)).
- **The `container` CLI is the only interface** to the runtime ([ADR 0001](docs/adr/adr_0001_cli_is_the_runtime_interface.md)).
- **Job code never runs on the host** ([ADR 0003](docs/adr/adr_0003_one_container_per_job.md)).
- **Runtime failures are system failures, script failures are job failures**
  ([ADR 0002](docs/adr/adr_0002_exit_status_classification.md)).
- **Generic relations only** — code, docs, ADRs, plans, commit messages and agent files name only
  Apple `container` and its runtimes, the CI systems integrated here and OCX. Describe any other
  tool by what it offers or needs
  ([ADR 0004](docs/adr/adr_0004_one_repository_for_ci_integrations.md)).

Security-sensitive paths:

- `internal/gitlab/**` — the stage script carries the job token into the container; image
  allow-list and mounts.
- `internal/container/**` — builds `container` CLI arguments from job input.
- `cmd/**` — runner flags and environment.
- `Taskfile.yml`, `githooks/**`, `scripts/**` — module proxy, git hooks and host scripts.

## Layout

| Package | Role |
|---|---|
| `internal/container` | `container` CLI client: run, list, exec, delete, label selection |
| `internal/gitlab` | Custom executor stages on top of `internal/container` |
| `internal/fakecli` | Fake `container` CLI for tests |
| `internal/version` | Build version and commit date |
| `cmd/gitlab-container-executor` | CLI entry point |
